## 1. Objetivo

Criar uma autoridade transversal que estabeleça uma linha mínima consistente para:

```text
entrada por teclado
→ foco perceptível
→ skip navigation
→ landmark principal
→ nome acessível
→ ativação semanticamente correta
```

A entrega não tenta corrigir automaticamente toda a plataforma. Ela cria uma autoridade reutilizável, audita o DOM e aplica somente reparos determinísticos.

---

## 2. Causa raiz

A auditoria encontrou:

- ausência de skip link;
- ausência de autoridade global para landmarks;
- `outline: none` em inputs, selects e textareas no CSS-base;
- foco visível dependente de regras locais;
- controles customizados sem contrato transversal de Enter/Espaço;
- placeholder usado visualmente como única descrição em alguns campos;
- Help Drawer com `button role="listitem"`, sobrescrevendo a semântica nativa;
- ausência de relatório sanitizado de controles sem nome.

Risco:

```text
usuário de teclado
→ entra na página
→ percorre header e sidebar inteiros
→ não encontra atalho para main
→ campo recebe foco sem indicador perceptível
```

## 4. Skip link

A autoridade cria no início do `body`:

```html
<a class="doke-skip-link"
   data-doke-skip-link="canonical"
   href="#doke-main-content">
  Ir para o conteúdo principal
</a>
```

Regras:

1. existe no máximo uma instância;
2. o `href` acompanha o landmark atual;
3. o clique move o foco para o main;
4. o link só aparece visualmente quando recebe foco;
5. funciona com teclado e tecnologias assistivas;
6. respeita reduced motion e forced colors.

---

## 5. Main landmark

Ordem de resolução:

```text
main
→ [role="main"]
→ [data-shell-main]
→ .page__content
→ .doke-page
→ #main-content
```

A autoridade não cria um segundo shell. Quando existe `main`, ele é preservado. Somente quando não existe main semântico uma surface candidata recebe `role="main"`.

O destino recebe:

```text
id="doke-main-content"
data-doke-main-landmark="canonical"
tabindex="-1"
```

O `tabindex="-1"` permite foco programático sem inserir o main na ordem natural de Tab.

A auditoria registra `mainCount`; múltiplos landmarks não são silenciosamente removidos.

## 6. Modalidade de entrada

Estados:

```text
KEYBOARD
POINTER
PROGRAMMATIC
```

A modalidade muda para teclado em:

- Tab;
- setas;
- Enter;
- Espaço;
- Escape.

Muda para pointer em:

- pointerdown;
- mousedown;
- touchstart.

O estado é publicado em:

```text
html[data-doke-input-modality]
```

Eventos não carregam texto digitado, seletor, ID de conta ou conteúdo da página.

## 7. Foco visível

Arquivo:

```text
assets/css/core/accessibility-experience.css
```

Cobertura:

- links;
- buttons;
- inputs;
- selects;
- textareas;
- summary;
- tabindex;
- role button;
- role link.

Estratégia:

```text
:focus-visible nativo
+
fallback por modalidade de teclado
+
data-doke-focus-visible
```

O CSS não utiliza `!important`.

Há suporte a:

- `prefers-reduced-motion`;
- `forced-colors`;
- outline com offset;
- reforço de border em campos.

Isso repõe o indicador perceptível removido pelo `outline: none` legado sem redesenhar componentes.

---

## 8. Nomes acessíveis

A autoridade considera nome existente quando há:

- `<label>` associado;
- `aria-labelledby`;
- `aria-label`;
- `title`;
- texto visível;
- `value` em input button/submit/reset;
- `alt` em imagens.

Placeholder não é tratado como nome acessível.

Reparo automático só ocorre quando existe:

```text
data-a11y-label
ou
title
```

Um controle sem nome é contado e reportado. A autoridade não fabrica rótulos como “Botão” ou “Ação”.

---

## 9. Semântica de teclado

A ativação automática é limitada a controles não nativos explicitamente declarados:

```text
[data-a11y-action]
[data-a11y-button]
[role="button"]:not(button):not(input):not(a)
```

Reparos:

```text
role="button"
tabindex="0"
```

Teclas:

```text
Enter
Espaço
```

Controles nativos permanecem sob responsabilidade do navegador. Nodes disabled ou `aria-disabled="true"` não são ativados.

## 10. Piloto — Help Drawer

O piloto corrige em runtime:

```text
input de busca
→ aria-label="Buscar na ajuda"

container role="list"
→ role="group"
→ aria-label="Tópicos de ajuda"

button role="listitem"
→ remove role
→ preserva semântica button

ícones e chevrons
→ aria-hidden="true"
```

O contrato de overlay do UX-NAV-001 é preservado.

Não há alteração visual no drawer.

## 12. Auditoria

A auditoria retorna somente contagens e estados:

```text
auditId
source
mainPresent
mainCount
skipLinkPresent
controlsChecked
unnamedControls
repairedNames
explicitActionsRepaired
pilotRepairs
```

Não são publicados:

- texto de controles;
- valores de inputs;
- IDs;
- URLs privadas;
- dados de conta;
- conteúdo de mensagens.

Novos nodes geram auditoria agendada via `MutationObserver`. Rotas prontas também disparam nova inspeção.
